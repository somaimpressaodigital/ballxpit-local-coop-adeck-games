# Building the mod

## Requirements

- Windows x64 and a compatible, locally installed copy of BALL x PIT.
- PowerShell 5.1 or newer.
- **.NET 8 SDK or newer**, including Roslyn's C# compiler. A runtime alone does not include the compiler. Download the SDK from [Microsoft](https://dotnet.microsoft.com/download/dotnet/8.0).
- The framework/base files bundled in `vendor/`.
- Game-specific interop assemblies generated by BepInEx on your own installation. These assemblies are deliberately excluded from this repository.

Compilation references the .NET runtime supplied with BepInEx, its core assemblies, the original co-op base, and the game's generated interop assemblies. It does not use a Unity Editor installation or redistribute game code.

## 1. Clone and prepare the game

```powershell
git clone https://github.com/somaimpressaodigital/ballxpit-local-coop-adeck-games.git
cd ballxpit-local-coop-adeck-games
.\InstallDependencies.ps1 -GamePath "D:\Games\BALL x PIT"
```

Close the game first. The script verifies the bundled framework archive's SHA-256 and copies BepInEx and the original base plugin into your chosen game directory. Back up existing framework files/configuration before running it over another mod setup.

Launch `Balls.exe` once. Wait for the menu after BepInEx finishes generating `BepInEx/interop`, then close the game. The first launch may require internet access for Unity libraries.

## 2. Compile

```powershell
.\Build.ps1 -GamePath "D:\Games\BALL x PIT"
```

The script discovers Roslyn in your installed SDK and compiles these production DLLs:

```text
out/
  BepInEx/
    plugins/
      LocalCoopTwoGamepads/TwoGamepads.dll
      LocalCoopBalance/CoopBalance.dll
    config/
      local.ballxpit.twogamepads.cfg
      local.ballxpit.coopbalance.cfg
```

`src/TwoGamepads` is the production source, including automatic localization. `ReleaseDiagnostics.cs` contains inactive compatibility stubs; the development gameplay/photo automation harness is not included. `src/CoopBalance` builds the separate balance plugin.

There are no developer-specific game paths in the build script. `references.json` lists reference paths relative to `GamePath`; `out/*.rsp` contains machine-local compiler response files and is ignored by Git.

Advanced compiler override, if you already have a compatible Roslyn distribution:

```powershell
.\Build.ps1 -GamePath "D:\Games\BALL x PIT" -CompilerPath "D:\Tools\Roslyn\csc.dll"
```

The initial repository build was verified with Roslyn 4.11 hosted by .NET 8, against the baseline game's local reference assemblies. Newer SDK compilers use the same build script but were not separately tested during repository preparation.

The script prefers the standard Windows x64 .NET installation over an old x86 installation on `PATH`. Use `-DotnetPath "D:\Tools\dotnet\dotnet.exe"` if your SDK is in a custom location.

## 3. Run rule tests

```powershell
dotnet run --project .\tests\RulesTests.csproj --configuration Release
```

These tests do not require the game. They cover language selection, controller identities/reconnection, aim updates at different frame rates, individual health/rescue rules, progression requirements, and the two-player confirmation gate. They do not exercise native Unity gameplay or physical controllers.

## 4. Install your build

With the game closed, copy the **contents** of `out/BepInEx` into the game's `BepInEx` directory. Keep both base dependencies installed. Preserve your existing configuration if you have customized it.

## 5. Package

```powershell
# Companion only: the two compiled plugins and configuration.
.\Package.ps1

# Complete: also includes the bundled BepInEx and original base.
.\Package.ps1 -Complete
```

Packages are written to `dist/` with the correct root layout and a SHA-256 manifest. They contain no game executable, `GameAssembly.dll`, generated interop, personal saves, runtime logs, or active test fixtures. No game process is started or closed by compilation/packaging.

## Troubleshooting

- **Missing SDK/compiler:** install the SDK rather than only the runtime, or provide `-CompilerPath`.
- **Missing BepInEx references:** run dependency installation and launch the game once before building.
- **Missing/renamed game APIs:** check the game, Unity, framework, and original-base versions against the compatibility baseline.
- **Security software flags `winhttp.dll`:** see [SECURITY.md](SECURITY.md). Do not disable antivirus protections as a build step.
- **DLL is locked:** close BALL x PIT before replacing installed plugins. `Build.ps1` writes to `out/` and does not overwrite the live game.
